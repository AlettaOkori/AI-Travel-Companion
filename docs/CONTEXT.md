# 华云天图 AI 旅伴 - 领域术语表

## 核心角色

### 游客（Tourist）
使用App的真人用户，是服务的接收方。在系统中以 `USER_DB` 中的用户条目表示（如 `zhang`、`lin`）。

### 导游分身
提供**行中讲解**服务的AI角色，与真实导游合作建设知识库和讲解内容。在游客到达景区后，通过对话形式提供实时导览服务。

**当前导游分身列表**（以zhang用户为例）：
- 王建国 AI — 前建筑师，建筑专家
- 陈月 AI — 国家地理签约摄影师
- 李伟民 AI — 本地historian，华侨故事
- 张晓雅 AI — 本地美食家
- 刘文山 AI — 生态学博士，自然教育
- 周明轩 AI — 当代艺术策展人

### AI规划师
提供**行前规划**服务的AI角色，拥有最高权限的景区数据与定制游规划经验。负责与游客进行多轮对话，完成行程规划任务。

**特征**：
- 统一品牌身份（旅行专属定制师）
- 支持自然语言交互
- 可生成可视化规划卡片

## 属性标签

### 用户画像（User Profile）
描述游客偏好的结构化标签集合，包括：
- **旅行节奏**：深度文化 / 轻松漫游 / 打卡效率 / 亲子互动
- **兴趣标签**：建筑遗产 / 地方饮食 / 非遗手艺 / 自然风景 / 摄影出片
- **授权同步**：历史偏好数据的使用授权

## 服务阶段

### 行前（Pre-trip）
游客抵达景区前的规划阶段，由AI规划师提供服务，完成7项准备任务。

### 行中（During）
游客在景区内的实时游览阶段，由**导游AI智能体**提供讲解服务。

导游AI智能体是一个具备感知、记忆、知识、决策能力的智能角色，而非简单的触发-响应系统：

**智能体能力**:
- **感知层**: 位置信息、时间、用户行为、景区实时状态
- **记忆层**: 行前规划、用户画像、对话历史、已讲内容
- **知识层**: 景区数据、知识图谱、金牌导游私有知识
- **决策层**: 判断何时主动讲解、何时回答提问、何时保持沉默

**交互模式 - 主动陪伴型**:

采用**综合平衡模式与主动陪伴**的策略：

1. **关键节点主动介绍**（预先规划）
   - 到达新景点时主动发起: "您现在看到的是龙胜楼..."
   - 触发条件: 位置/蓝牙信号确认 + 行前规划的时间节点双重验证
   - 内容来源: 预先学习的金牌导游讲法

2. **有趣细节主动分享**（情境感知）
   - 看到特定建筑细节时: "您注意到这面墙上的砖有什么不同吗？"
   - 结合用户画像判断兴趣点（如摄影爱好者→光影变化，亲子→互动提问）

3. **响应式对话**（被动应答）
   - 用户提问时即时回答
   - 结合上下文进行延伸（如用户连续问3个建筑问题→主动提出"要系统讲讲建筑材料吗？"）

**约束**: 不采用视线追踪等技术，仅基于位置+时间+对话上下文进行决策。

#### 智能体记忆机制

导游AI智能体具备分层记忆能力，支持跨时间维度的个性化服务：

**短期记忆（单次行程）**:
- **保留时长**: 行程期间（1-3天）
- **内容**: 完整对话历史、已讲解景点、用户实时提问
- **用途**: 避免同一天重复讲解，保持对话连贯性
- **场景A**: 游客昨天听了自力村讲解，今天续游 → AI跳过已讲内容，接续新景点

**会话记忆（中断恢复）**:
- **保留时长**: 实时同步
- **内容**: 当前对话上下文、讲解进度、用户未回复的问题
- **场景B**: 游客中途退出App → 重新进入后恢复对话状态，从断点续讲

**长期记忆（跨行程）**:
- **保留时长**: 永久保留，但压缩存储
- **内容**: 用户画像（旅行节奏、兴趣标签）+ 历次行程摘要
- **存储形式**: 非原始对话原文，而是结构化摘要
  - 例: "2025年春，开平碉楼，主导游:王建国AI，兴趣焦点:建筑摄影，知识获取:材料演变、防御构造"
- **场景C**: 半年后重游 → AI基于摘要"认出"游客

**重游专属体验**:
- 触发条件: 同一用户ID + 同一景区 + 时间间隔>30天
- AI主动问候: "好久不见，您上次来是去年春天，当时对建筑摄影特别感兴趣，这次想看点不一样的吗？"
- 知识去重: 自动跳过上次已深入讲解的内容，推荐新知识点
- 进阶路线: 基于上次掌握程度，推荐更深度的游览路线

#### 数据持久化与隐私策略

**存储原则**: 服务优化与隐私保护的平衡

**位置数据**:
- **实时使用**: GPS定位用于触发讲解、导航
- **本次行程存储**: 完整轨迹随用户账号存储，支持行中回顾和游后沉淀
- **长期保留**: 行程结束后保留关键信息（到访景点、停留时长、游览顺序），用于重游推荐和个性化优化
- **删除权利**: 用户可随时删除历史轨迹

**语音数据**:
- **仅实时转文字**: 语音输入实时转为文本，不存储原始录音
- **文本保留**: 转写后的对话文本按"短期记忆"规则保留

**对话历史**:
- **完整记录**: 单次行程期间完整保留，支持中断恢复
- **摘要存储**: 行程结束后压缩为结构化摘要长期保存
- **原文删除**: 完整对话原文在摘要生成后删除（7天内）

**用户权利**:
- **数据导出**: 支持导出个人数据（画像、行程记录、知识图谱）
- **数据删除**: 支持删除账号及关联数据
- **透明度**: 明示数据使用范围

**G端数据共享（B2G2C模式）**:
- **共享边界**: C端用户数据仅过滤出关键指标后向G端平台共享
- **共享内容**: 匿名化后的客流热力、景点停留时长、满意度统计、热门知识点
- **不共享内容**: 个人身份信息、完整对话内容、精确位置轨迹
- **目的**: 支持文旅监管部门掌握景区运营态势，优化公共服务

### 游后（Harvest）
游览结束后的知识沉淀阶段，生成行程档案和知识图谱。

## 导游分身选择机制

### 选择时机
- **行前预选**：AI规划师在行前规划阶段推荐并允许预选导游分身
- **行中确认/更换**：游客到达景区后可最终确认或更换导游分身
- **更换限制**：一个行程同一时间只能绑定一个导游分身（保持对话连续性）

### 付费机制考量
- 中途更换导游分身涉及付费机制设计（待明确）
- 可能与讲解时长、景点覆盖度相关

### 默认分配策略
当游客未主动选择导游分身时：
- **平台自建AI导游**：提供非真实导游分身的平台标准导游服务
- 使用统一的景区知识库和数据
- 保证基础服务质量

### 未来扩展
- **专家会诊制**（待实现）：主导游分身无法回答时，可临时咨询其他分身专家
- 所有导游分身共享景区知识库和数据

## 行中讲解触发机制

### 混合触发策略
结合多种触发方式，平衡自动化与用户体验：

#### 1. 手动触发（主要方式）
- 底部行程条显示当前位置和下一目标
- 游客点击景点节点主动触发讲解
- 给予用户控制权，避免打扰

#### 2. 定位触发（辅助方式）
- 游客进入景点地理围栏范围时推送轻提醒
- 提醒文案："您已接近龙胜楼，是否开始讲解？"
- 用户确认后启动，不强制自动播放

#### 3. 时间参考（辅助判断）
- 当用户在某一区域停留超过阈值（如5分钟）
- 推送询问："检测到您已在龙胜楼附近停留，是否需要导览？"

### 防重复触发机制
- 同一景点讲解完成后标记"已听"
- 走回头路时提供"重新听"选项而非强制播放
- 避免GPS抖动导致的误触发

## 知识库架构

### 第一层：景区基础数据（官方权威）
**来源**：景区API对接（只读）  
**内容**：建筑信息、地理数据、开放状态、人流数据、天气数据  
**更新频率**：实时/小时级

### 第二层：知识图谱（结构化解读）
**来源**：平台专家团队维护 + 导游共建（需审核）  
**内容**：建筑知识、历史知识、艺术知识、民俗知识  
**更新流程**：导游提交 → 专家审核 → 入库共享  
**示例**：龙胜楼修缮发现的明信片、材料演变史、防御构造原理

### 第三层：导游分身个性（差异化表达）
**来源**：真实导游授权 + AI训练  
**内容**：讲解风格、专业侧重、语音特征、表达方式  
**约束**：**不得编造与事实不符的内容**  
**实现**：基于第一、二层事实的个性化转述与演绎
